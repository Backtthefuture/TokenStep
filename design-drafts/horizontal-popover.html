TokenStep 浮窗三版设计稿

当前菜单栏浮窗是 412px 竖向叠卡，一加 Agent 和订阅额度就会越拉越长。下面三版都改成横扫：保留健身环记忆点，把「今日走了多少步 / 各 Agent 贡献 / 订阅还剩多少」放进同一视窗。数字是示意，用来看信息层级，不是真实账单。

现状：竖版卡片栈

PopoverPanelView 固定宽 412px，从上到下：标题、今日圆环、Agent 一行摘要、Codex/Claude 额度、榜单、页脚。Token Island 展开虽是 356×238，工具行仍写死 Codex 与 Claude Code。

问题不是不好看，是装不下。GLM / Kimi / Grok 额度一旦打开，用户要点击后向下滚才能看完「会不会被限流」。

竖版把「环」当英雄模块是对的，但额度与 Agent 被压成附录。横版要做的是：环仍然一眼能认，右侧让订阅和 Agent 进入主视线。

方案 A · 横版健身台（推荐默认）

左栏深色圆环承接现有品牌；中栏按 Agent 列出 Token、请求、占比，不再写死两家；右栏四张额度胶囊覆盖 Codex / Claude / GLM / Kimi，Grok 用第五张的位置规则：有数据才出现。

这是对现浮窗的「旋转」而不是重做。用户仍先看到圈数，再扫一眼谁在干活、哪张订阅快见底。

方案 B · 工作台

给同时开多套订阅的人看数。中表直接露出 Token、请求、工具调用、缓存命中——这些字段 DailyAgentWork 里已经有，只是界面没用。右栏按「剩余百分比」排序，见底的订阅置顶并标暖色。

比 A 更像报表，截图分享会变「日报」而不是「步数卡」。建议做成显示密度开关，而不是替换默认。
