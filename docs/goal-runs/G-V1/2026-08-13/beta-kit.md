# V1-T04 Beta 理解度测试工具包（待用户招募后执行）

> 用途：10 名符合"每天用 Codex/Claude Code 且常驻菜单栏"描述的 Beta 用户，验证 5 秒内能否判断数据可信度。
> 执行人：用户（招募 + 主持）；本包提供全部材料与判分标准。不新增遥测，只记录答案与反馈。

## 测试材料（截图任务，随机排序呈现）

用 `script/render_freshness_states.sh` 生成的 `freshness-states.png` 作为固定截图组（10 行：9 状态 + 金额示例），按行裁切为单状态卡片，随机排序编号。

每张截图问三个问题（被试看完 5 秒后立即口头回答，主持人记录）：

1. 这个数字/状态是**官方数据、本地记录、估算，还是已过期**？
2. 现在展示的值能不能信？（能/不能/不确定）
3. 图里"消耗金额 $12.34"是什么？（API 估算 / 官方账单 / 订阅额度）

## 通过条件（PRD §5.6）

- ≥8/10 在 5 秒内正确指出官方数据 / 本地记录 / 估算 / 是否过期
- ≥7/10 认为比 v0.1.48 更容易判断
- **0 人**把本地估算误认为官方额度或实际账单

## 判分词表（主持人用）

| 展示元素 | 正确答案 |
|---|---|
| 额度卡 Codex/Claude 剩余百分比 | 官方数据（供应商接口） |
| 今日 Token 消耗圆环 | 本地记录（本地日志解析） |
| 消耗金额（估算） | 估算（API 列表价，非账单） |
| 同步失败 · 最后成功 5 分钟前 | 已过期（展示的是最后成功值） |
| 部分来源失败 | 本地记录，部分来源缺席/失败 |
| 暂无数据 | 从未成功（不是 0） |

## 真实使用环节

截图测试后，请被试在自己 Mac 上装同版本使用 10 分钟，然后问：

1. 你现在能说出今天的数据是否可信吗？怎么判断的？
2. 哪个标签/位置对你最有用/最困惑？
